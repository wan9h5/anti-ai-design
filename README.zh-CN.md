一套通用的界面设计约束与审查规范，帮助 AI 减少套路化、空心化和模板化的输出，使界面贴合真实使用者、真实任务和开发约束。

它通过 Agent Skill 介入创建、审查与重构：先理解场景，再组织信息、选择视觉方向并实现交互。目标是同时提高视觉质量、使用体验与开发可落地性。

## 面向谁

直接使用者是通过 Codex 等 Agent 开发界面的开发者、设计师和业务专家；最终服务对象是他们产品的实际使用者。两者可能是同一个人，也可能完全不同。不要把开发者的专业知识、审美偏好或操作习惯自动当成最终使用者的需求。

适用于普通用户产品、内部后台、专业工具、科研平台及 AI for Science 等场景。行业与用户熟练程度属于具体项目输入，Skill 不预设科研用户、低密度布局或固定视觉风格。业务专家未提出设计要求时，Agent 仍应主动处理信息层级、视觉节奏与交互反馈。

“Anti-AI”指对缺乏依据的设计默认值进行约束，不是识别 AI 作者。卡片、渐变、圆角或高密度都可以合理；区别应来自任务组织、真实内容和有意识的视觉选择，而不是刻意求异。

## 工作流程

1. **明确场景**：区分开发者与最终使用者，确定主要任务、内容、设备、现有设计系统和实现约束；只追问会改变关键决策的问题。
2. **组织信息**：按任务决定页面结构与优先级，选择合适的密度；不因缺少设计要求就套用概览面板。
3. **确定视觉方向**：把字体层级、空间节奏、色彩与组件选择联系到具体内容和使用情境；兼顾辨识度与熟悉的操作方式。
4. **创建或修改**：遵循项目技术栈，落实主要交互与状态，清楚标记演示数据和能力边界。
5. **审查并验证**：按需使用 52 条诊断规则，考虑合理例外，修复具体问题并报告实际检查结果。

这套流程随任务缩放，小改动不需要完整工作坊。AI4S / 生信面板是应用场景之一，可使用领域数据与分析流程作为输入，通用规则保持不变。

## 使用方式

把整个仓库作为 `anti-ai-design` 文件夹放到你的 Agent 支持的 skills 目录。Codex 可使用 `$CODEX_HOME/skills/anti-ai-design`；未设置 CODEX_HOME 时使用 `~/.codex/skills/anti-ai-design`。保留 references 与 workflows，不能只复制主文件。

示例请求：

- “使用 $anti-ai-design，从零实现一个供值班工程师处理告警的界面；用明确标记的合成数据制作可交互原型。”
- “使用 $anti-ai-design 审查这张截图，区分可见事实和行为假设，保留有效的领域习惯，按影响给出修改。”
- “使用 $anti-ai-design 重构这个核对表格，保持横向比较效率并检查修改后的任务流程。”

Skill 的工作指令使用英文以便复用，要求交付时使用用户语言。主文件只包含共享决策与加载入口，详细参考按问题加载。

## 原则

先明确用户任务、决策和真实能力，再选择结构、密度、文案与视觉语言。颜色、渐变、圆角、卡片、深色主题、衬线字体或留白本身不能证明界面质量，也不能证明内容来自 AI。

每个发现都连接到具体任务，并区分可观察事实、规范要求、设计指南和待验证假设。截图不能证明键盘操作、真实性能、数据来源或持久化行为。专业表格可以很密集，品牌表达可以很丰富；例外必须有任务依据。

交付应包含用户要求的界面、实现或具体改动。按钮与状态必须符合实际能力，模拟数据与模拟运行在使用位置清楚标注。审查重构时保留有效的能力边界说明与可追溯信息。

## 当前优先方向

先用真实页面检验这套规范是否满足开发者与使用者的目标，再根据具体失败补规则。建议从一个关键任务页面开始，使用真实长度的内容，检查视觉主次、交互完成度和实现成本。跨模型基准与大规模用户研究属于后续可选研究，不是使用本 Skill 的前提。
