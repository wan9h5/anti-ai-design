# Anti-AI Design

用于从零生成、审查和重构产品界面的开源 Agent Skill。

[English](README.md) · [主 SKILL.md](SKILL.md) · [证据登记](references/evidence.md) · [评估案例](tests/scenarios.json) · [初版实际评估](tests/evaluation-report.md)

研究范围包含产品推理、信息架构、密度、布局、视觉同质化、微文案、交互、数据可视化、可访问性、性能和功能真实性。52 个诊断条目各自给出可观察信号、潜在影响、改进办法、合理例外、验证方法与证据类型。

## 使用方式

把整个仓库作为 `anti-ai-design` 文件夹放到你的 Agent 支持的 skills 目录。Codex 可使用 `$CODEX_HOME/skills/anti-ai-design`；未设置 CODEX_HOME 时使用 `~/.codex/skills/anti-ai-design`。保留 references 与 workflows，不能只复制主文件。

示例请求：

- “使用 $anti-ai-design，从零实现一个供值班工程师处理告警的界面；用明确标记的合成数据制作可交互原型。”
- “使用 $anti-ai-design 审查这张截图，区分可见事实和行为假设，保留有效的领域习惯，按影响给出修改。”
- “使用 $anti-ai-design 重构这个核对表格，保持横向比较效率并检查修改后的任务流程。”

Skill 的工作指令使用英文以便复用，要求交付时使用用户语言。主文件只包含共享决策与加载入口，详细参考按问题加载。

## 原则

先明确用户任务、决策和真实能力，再选择结构、密度、文案与视觉语言。颜色、渐变、圆角、卡片、深色主题、衬线字体或留白本身不能证明界面质量，也不能证明内容来自 AI。

每个发现都连接到具体任务，并区分可观察事实、规范要求、设计指南和待验证假设。截图不能证明键盘操作、真实性能、数据来源或持久化行为。专业表格可以很密集，品牌表达可以很丰富；例外必须有任务依据。

交付应包含用户要求的界面、实现或具体改动。按钮与状态必须符合实际能力，模拟数据与模拟运行在使用位置清楚标注。审查重构时保留有效的能力边界说明与可追溯信息。

## 校验与研究边界

运行：

```sh
python scripts/validate.py .
python -m unittest discover -s tests -p "test_*.py"
```

这些检查用于包结构、内部链接、证据引用、反模式记录及公开内容检查。真实行为评估方法见 [测试说明](tests/README.md)，已执行的生成、审查与重构记录及合成界面见 [初版评估](tests/evaluation-report.md)。12 个评估案例尚未全部执行。结构检查通过不代表易用性提高、WCAG 整体符合或安全审计完成。


初次发布已在本地通过包校验和回归测试。当前 GitHub 凭据缺少工作流文件写入权限，因此公开分支未启用自动 CI；离线 ZIP 保留该工作流定义。

本版是基于一手规范、设计系统指南和原作者研究的系统整理。没有证明这些模式在 AI 界面中普遍出现的统计研究，也没有完成跨模型或真实用户效果实验。详细限制见 [证据登记](references/evidence.md)。
