# Contributing

Changes should improve a real decision the skill makes. Avoid accumulating style prohibitions or repeating generic advice.

For a new/changed diagnostic, provide an observable trigger, task consequence, concrete repair, valid exception, and a check that can refute the concern. Name the evidence basis. New primary sources belong in references/sources.json and references/evidence.md with a verified date, supported claim, and limitation.

Keep shared instructions short and subject guidance selectively loaded. Preserve user scope and authorization. Do not add mandatory external publishing, dependence on a specific UI framework, or permission prompts unsupported by the actual task.

Run the offline validator and regression tests. For behavior-changing edits, evaluate relevant synthetic scenarios and retain useful counterexamples. Record what was actually evaluated.

Do not submit credentials, private screenshots/conversations, real participant data, proprietary assets, or production datasets. Use original synthetic examples. A suspected credential exposure should be reported privately through the repository owner's GitHub contact path when available; never post the secret in an issue. Contributions are licensed under the repository's MIT terms.
