# 中文工作台：双语文案与语言标记审查

结论：应修正的是“说明”下完整英文段落的语言标记；不应把 `RNA-seq workflow`、`sample_id` 或 `SYN-01` 一律当作语言切换缺陷，也不必为了中文一致性强行翻译领域名称与技术标识。

## 范围与任务

已检查 supplied `inputs/bilingual.html` 的实际文本及 HTML 标记，采用 anti-ai-design 的 review 工作流与 AP023、AP045。已知领域用户使用英文工作流名称和技术标识；任务是选择分析流程、核对样本标识、查看参数后运行。是否熟练阅读完整英文说明未知，不能从术语熟悉程度推断。

仅作源代码审查，未渲染页面、操作浏览器或测试屏幕阅读器。未判断视觉风格、AI 作者身份、整体 WCAG 符合性，也未验证分析执行能力。

## 主要发现：完整英文说明继承了中文语言声明

- **位置与观察**：根元素为 `<html lang="zh-CN">`；“说明”标题后的第二个 `<p>` 是完整英文说明与运行前提示，包含 “Review the parameters before running.”，却没有 `lang="en"`，祖先也没有英文声明。
- **任务影响**：辅助技术可能按中文语言规则处理这段英文，影响听取流程解释和运行前核对提示。实际发音效果尚未测试；源码中的语言语义问题则已观察到。
- **依据**：WCAG 2.2 **3.1.2 Language of Parts，AA** 要求可程序化确定段落或短语的人类语言，并对专有名称、技术术语、无法确定语言的词以及已融入周边语言的词或短语设例外。该段包含普通英文句法与操作指令，不能因其中涉及技术流程就把整段视为技术术语例外。来源：[W3C WCAG 2.2，3.1.2](https://www.w3.org/TR/WCAG22/#language-of-parts)，本次已核对规范正文。
- **优先级 / 置信度**：中等 / 高。标记缺失确定；用户遇到的具体发音问题和严重程度仍需实测，没有证据把它判为任务阻断。
- **修正**：若保留英文原文，只为第二个 `<p>` 添加 `lang="en"`，保留整页 `lang="zh-CN"`。不要给包含中文操作说明的第一个段落整体添加英文声明。
- **验证**：检查第二段最终 DOM 的有效语言为英语，页面及中文标题、按钮仍为中文；再用支持中英文语音切换的屏幕阅读器听读两个段落及字段标签，确认没有把中文句子整体切换为英语。

## 应保留的例外与有效选择

| 实际内容或标记 | 判断与处理 |
| --- | --- |
| `<html lang="zh-CN">`，中文标题“分析工作台”“说明”和按钮“查看参数” | 主界面语言清楚，保留中文页面声明及具体动作标签。 |
| 第一段“选择 RNA-seq workflow 并检查 sample_id 后运行。” | 句子主体是中文；所嵌领域流程名称可保留。已知用户使用此称呼，不凭英语字符就要求翻译或给整句改语言。 |
| 字段名称 `sample_id`（第一段及 `<label>` 内） | 技术标识应保持与数据字段、文档中的拼写一致；可按技术术语例外处理，不要求逐个添加英文语言声明。 |
| 输入值 `SYN-01` | 样本标识不是普通英文说明；没有证据将其视作需要 `lang="en"` 的英文短语。 |
| `<label>sample_id <input value="SYN-01"></label>` | 字段有持续可见的标签，且输入嵌套于原生 label 中；这项结构应保留。实际辅助技术读法未测。 |

规范的术语例外不保证每种语音引擎都能理想地读出标识；若用户反馈具体发音问题，可针对名称补充合适解释或读法，不必全局翻译或标记每个英文 token。

## 文案选择与未决检查

把完整英文说明翻译为中文是可选的内容改进，不是 3.1.2 强制翻译要求。若目标用户更易理解中文，可使用：“此流程将比对测序读段，并估算基因表达量。运行前请检查参数。”翻译前需确认领域措辞符合实际流程。仅凭现有输入，不能断言用户读不懂英文或混合语言必然降低效率。

保留英文时，添加 `lang="en"` 即是针对已观察问题的最小修正。后续可让代表性用户复述流程作用和运行前动作，以判断是否需要中文版说明；这与屏幕阅读器语言切换验证是两项不同检查。

本片段没有流程选择控件、运行控件、脚本或参数展示实现，因此不能证明完整任务可完成。“查看参数”的实际效果、流程执行与恢复路径均未验证；这些边界不影响本次针对段落与术语例外的结论。
