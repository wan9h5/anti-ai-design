# Counterexamples to style rules

These examples stop the catalog from becoming a visual blacklist.

| Tempting rule | Valid counterexample | Better decision |
| --- | --- | --- |
| Replace cards with tables. | A collection of heterogeneous visual stories supports browsing. | Choose cards for summaries; align rows for comparison/search where needed. |
| Always add whitespace. | A reconciliation task needs many aligned values and rapid switching. | Tune density, hierarchy, targets, and legibility with real work. |
| Put every task in a wizard. | Inputs and outputs need repeated what-if comparison. | Keep coupled work together; stage independent submissions. |
| All chart axes must start at zero. | A line chart shows small variations in a meaningful range. | Protect bar magnitude; disclose non-zero analytical ranges appropriately. |
| Every control must be 44 CSS px for WCAG AA. | An adequately spaced undersized target may meet 2.5.8. | Apply the actual 24 CSS px criterion and exceptions; aim larger when useful. |
| Mixed languages always fail WCAG. | A technical term is part of the audience's working vocabulary. | Inspect actual passage language semantics and named exceptions. |
| Bright brand expression is generic. | A user explicitly requests an expressive arts/editorial experience. | Respect the brief and preserve comprehension/accessibility. |
| Dark result surfaces or serif headings are AI tells. | A coherent hierarchy uses either successfully. | Inspect task fit; do not infer authorship. |
| Disable anything unimplemented. | An unavailable control without explanation hides the next step. | Prefer a labeled prototype or explained capability boundary appropriate to context. |
| One accessibility scan proves conformance. | Keyboard/task semantics fail despite an automated pass. | Combine applicable automated, manual, and assistive-technology evaluation. |

See the [evidence register](../references/evidence.md) for the basis and limitations.
